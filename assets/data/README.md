# دادهٔ وقف و ابتدا

این پوشه داده‌های «کجا بایستیم / از کجا از سر بگیریم» را نگه می‌دارد. دو فایل:

| فایل | نقش | چگونه ساخته می‌شود |
|---|---|---|
| `waqf-signs.json` | نشانه‌های چاپی مصحف مدینه (منبع پایه، قطعی) | `npm run waqf` |
| `waqf-overrides.json` | احکامِ کتاب‌های وقف و ابتدا (اختیاری) | `npm run waqf:from-csv` یا دستی |
| `waqf-overrides.example.json` | نمونهٔ همان قالب (فقط مستندسازی) | — |

`waqf-overrides.json` در گیت نیست: اگر وجود نداشته باشد، برنامه فقط نشانه‌های مصحف را
نشان می‌دهد و خطا نمی‌دهد.

---

## ۱. نشانه‌های مصحف — `waqf-signs.json`

خودِ SVG مصحف هر نشانِ وقف را دوبار رمزگذاری می‌کند:

```xml
<!-- الف) مسیرِ نوع‌دار داخل گروه لیگاچر -->
<path id="md-path-073-01" data-type="waqf" data-waqf="waqf sali" d="…"/>

<!-- ب) گروه کلمه‌ای که متنش فقط خودِ نشان است -->
<g id="md-word-073" data-surah="017" data-aya="110" data-line-number="06"
   data-hafs="ۖ" data-word-index-in-ayah="7">
```

صورت (ب) باعث می‌شود هر نشان با **سوره:آیه + جای کلمه در آیه** قابل نشانی‌دهی باشد؛
`scripts/build-waqf-data.py` همان را می‌خواند.

### ساختار

```json
{
  "meta": { "marks": 4486, "mark_counts": { "jaiz": 2083, "…": 0 } },
  "marks": {
    "17:110": [
      {
        "page": 293, "line": 6, "word": 7, "svg_id": "md-word-073",
        "mark": "ۖ", "kind": "sali",
        "prev_word": 6, "prev_text": "ٱلرَّحۡمَٰنَ",
        "next_word": 8, "next_text": "أَيّٗا"
      }
    ]
  }
}
```

- `word` = `data-word-index-in-ayah` خودِ نشان. چون نشان هم شمرده می‌شود، این شماره از
  شمارهٔ کلمهٔ منطقی در QCF4 جلو می‌افتد؛ برای تطبیق با QCF4 از `svg_id` استفاده کن.
- `prev_*` / `next_*` کلمه‌های همسایه در ترتیب خواندن‌اند؛ `prev_key` / `next_key`
  فقط وقتی می‌آید که همسایه مال آیهٔ دیگر باشد (مثلاً نشانِ ۞ اول آیه).
- نشان‌های معانقه `pair` (`a` یا `b`) و `pair_id` مشترک دارند.

### `kind`ها

| `kind` | نشان | در مصحف | معنی |
|---|---|---|---|
| `lazim` | ۘ | م | وقف لازم — باید ایستاد |
| `jaiz` | ۚ | ج | وقف جائز — ایستادن و رد شدن یکسان |
| `qila` | ۗ | قلی | وقف اولی — ایستادن بهتر است |
| `sali` | ۖ | صلی | وصل اولی — رد شدن بهتر است |
| `muanaqa` | ۛ | ۛۛ | معانقه — فقط روی یکی از دو نشان بایست |
| `hizb` | ۞ | — | ربعِ حزب (بخش‌بندی، نه حکم وقف) |
| `sajda` | ۩ | — | سجدهٔ تلاوت |

شمارِ کل در ۶۰۴ صفحه: **۴۴۸۶ نشان در ۲۶۹۰ آیه**
(جائز ۲۰۸۳، صلی ۱۶۵۱، قلی ۵۱۱، حزب ۱۹۹، لازم ۲۱، سجده ۱۵، معانقه ۶).

### ساخت و بازبینی

```bash
npm run waqf          # ساخت از vendor/mushafdatabase-svg-v1.01.tar.gz
npm run waqf:check    # مقایسهٔ فایل گیت‌شده با همان منبع (CI همین را اجرا می‌کند)
```

اسکریپت دو بررسی داخلی هم دارد: تعدادِ مسیرهای `data-waqf` باید با تعداد گروه‌های
نشان یکی باشد، و ترتیب کلمه‌ها در هر آیه باید صعودی بماند.

## ۲. احکام کتاب — `waqf-overrides.json`

برای داده‌ای مثل **منار الهدی فی بیان الوقف و الابتدا** که حکمِ هر وقف را
(تام/کافی/حسن/…) و جای ابتداء را جدا از نشانه‌های چاپی می‌گوید.

### ساختار JSON

```json
{
  "meta": { "source": "منار الهدی (اشمونی)" },
  "waqf": [
    { "verse": "17:110", "word": 7, "type": "kafi", "ar": "کاف",
      "fa": "وقف کافی", "reason": "تمام‌شدن جمله", "ibtida_word": 8 }
  ],
  "ibtida": [
    { "verse": "1:5", "word": 6, "type": "tam", "fa": "ابتدای تام",
      "note": "پس از وقف تام، از اینجا آغاز کن" }
  ]
}
```

- `verse` = `سوره:آیه` با عدد لاتین.
- **یک قاعدهٔ شماره‌گذاری:** همهٔ `word`ها شماره‌گذاری خودِ مصحف‌اند، یعنی همان
  `data-word-index-in-ayah` که در `waqf-signs.json` آمده و در آن **نشانِ وقف هم یک
  جایگاه شمرده می‌شود**. با شمارهٔ کلمهٔ منطقیِ QCF4 فرق دارد.
- سطرِ `waqf` می‌تواند نشان را با `word` (جای خودِ نشان) **یا** با `prev_word`
  (کلمهٔ پیش از وقف) نشانی کند؛ اولی اولویت دارد. اگر هیچ‌کدام به نشانی نخورد و
  `prev_word` شمارهٔ نشانِ موجودی باشد، حکم به همان نشان می‌چسبد تا نشان تکراری
  ساخته نشود.
- سطرِ `waqf` که با یک نشانِ چاپی همان آیه یکی شود، به آن نشان **حکم** می‌دهد
  (`type/ar/fa/reason` و در صورت نیاز `ibtida_word`)؛ سطرِ بی‌همتا به‌عنوان حکمِ
  کتاب‌محور، مستقل نمایش داده می‌شود.
- `ibtida` جای ازسرگیری را حتی جایی که هیچ نشانی چاپ نشده ثبت می‌کند؛ `word` آن
  هم با همان شماره‌گذاری مصحف است (معمولاً `next_word` همان نشان).

### از CSV

```bash
./scripts/convert-waqf-csv.py \
  --waqf manar-waqf.csv --ibtida manar-ibtida.csv \
  --source "منار الهدی (اشمونی)" \
  --out assets/data/waqf-overrides.json
```

`manar-waqf.csv`:

```csv
verse,word,prev_word,type,ar,fa,reason,ibtida_word
17:110,7,,sali,صلی,وصل اولی,جمله تمام نشده,8
5:73,,8,lazim,م,وقف لازم,معنا با وصل به‌هم می‌خورد,
```

`manar-ibtida.csv`:

```csv
verse,word,type,fa,note
1:5,6,tam,ابتدای تام,پس از وقف تام
```

`type` را می‌توانی با نام عربی/فارسی هم بنویسی (تام، کافی، حسن، لازم، جائز، قلی،
صلی، معانقه، قبیح، سجده، حزب، سکته)؛ مبدل آن‌ها را به کلید لاتین یکسان تبدیل می‌کند.
سطرهای بد (کلید آیهٔ نامعتبر یا بی‌`word` و بی‌`prev_word`) با شمارهٔ خط گزارش و رد
می‌شوند، بی‌صدا نه.

خروجیِ نمونهٔ آماده در `waqf-overrides.example.json` است؛ برای فعال‌شدنش کافی است
همان فایل را با نام `waqf-overrides.json` ذخیره کنی.
